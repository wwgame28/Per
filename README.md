# ШТАБ — Анна и локальная команда для VK

Go + SQLite + VK Bots Long Poll + один локальный llama-server. Платные AI API не используются.

Этот репозиторий заменяет прежний «Периметр» по указанию владельца. Его исходное состояние сохранено в ветке [`backup-before-shtab-20260925`](https://github.com/wwgame28/Per/tree/backup-before-shtab-20260925), коммит `5c2a1b2ed441a6595482b9a7e686a2dccdbf14cc`. История не переписана. Исходники прежнего «ШТАБ» не были доступны: это самостоятельная реализация предоставленного ТЗ, а не правка найденного старого backend.

## Что реализовано

- Анна — секретарь Данила и администратор; Виктор — менеджер; Мира — аналитик; Нора — редактор; Ева — дизайнер; Алекс — разработчик; Макс — проверяющий. Имена, роли, характеры и краткая память разделены.
- Цепочка подготовки поста: Анна → Мира → Анна → Нора → Анна → Ева → Анна → Макс → структурированное намерение Анны. При замечаниях — одна доработка Норой и повторная проверка Максом. Каждый ход — отдельный запрос к модели. При отказе проверки пост не публикуется.
- Один worker, одна модель, `--parallel 1`, один поток CPU. HTTP/Long Poll и команды владельца не ждут завершения inference.
- JSON-намерения, строгая валидация, фиксированное сообщество и допустимые методы. Пользовательские сообщения никогда не интерпретируются как команды инструментам.
- HIGH-действия требуют `/approve ACTION-…` или `/reject ACTION-…` от `DANIL_VK_ID` в личном диалоге. Подтверждение одноразовое, связано с неизменяемыми аргументами и истекает через 24 часа. CRITICAL-инструментов нет; блокировка владельца/администраторов запрещена даже после подтверждения.
- SQLite: действия, очередь, события, диалоги агентов, память, контент-план, настройки, антиспам. `/anna log`, `/anna report`, `/anna approvals` показывают реальные записи.
- Автономные ответы на личные сообщения и новые комментарии; точный антиспам по фразам, добавленным Данилом; лимиты, дедупликация, cooldown, handoff и blacklist.
- Отложенные публикации — через сохраняемую очередь, без `cron`. После рестарта расписание сохраняется. Если сервер выключен в назначенное время, задание будет обработано после запуска. При паузе публикаций нет.
- Инициатива включается отдельным интервалом и требует заданных целей сообщества. Ежедневные отчёты **не рассылаются**: только `/anna report`.
- При ошибке сети после записи запроса результат `UNKNOWN`: автоматического повторения записи нет. Это предотвращает дубли постов/ответов, но требует ручной проверки в VK.
- `/anna emergency-stop` сохраняет паузу и отменяет активный inference/HTTP-контекст. `/anna resume` продолжает очередь. Уже принятый VK запрос отозвать невозможно.
- Сообщение «Анна, не публикуй сегодня ничего» отменяет ожидающие публикации до конца дня в `TZ`.

## Запуск на Amvera с iPhone

1. Подключить **этот** репозиторий `wwgame28/Per`, ветку `main`, к приложению Amvera. Проверить, что не используется старый Python-конфиг. В репозитории один `amvera.yml`, окружение Docker, порт **8080**, постоянные данные **/data**.
2. В настройках приложения задать секреты и переменные из таблицы ниже. Не отправлять токены в VK-чат, LLM или GitHub.
3. В VK включить сообщения сообщества и Bots Long Poll, версию API 5.199 и события `message_new`, `wall_reply_new`. Создать токен сообщества с необходимыми правами. Данил должен первым написать сообществу, чтобы оно могло присылать ему ответы.
4. Для операций, которым необходим пользовательский токен, самостоятельно выдать разрешённый VK токен администратора с нужными правами. Возможность получения такого токена зависит от приложения и ограничений VK. Если его нет, сообщения работают с токеном сообщества, но часть администрирования недоступна.
5. Запустить сборку. При первом запуске скачивается Qwen3-0.6B Q4_K_M, **396 705 472 байта**, проверяется SHA-256. Бот управления запускается до скачивания; при отказе модели продолжает работать.
6. Написать `/anna status`, затем `/anna knowledge …`, `/anna goals …`, `/anna rules …`. Проверить `/anna do прочитай стену` или точный `/anna tool {"tool":"vk.get_wall","arguments":{}}`.
7. Для первого поста: `/anna publish короткая идея поста`. Проверить результат в VK и `/anna log`. Для инициативы задать `INITIATIVE_INTERVAL_MINUTES=1440` и включить `/anna autonomy on`.

Приложение **не развёрнуто автоматически в аккаунте Amvera**: в данной сессии нет его конфигурации, идентификатора сообщества и VK-токенов. Запись настоящего поста в VK не проверялась.

## Переменные

| Переменная | Назначение / значение |
|---|---|
| `VK_TOKEN` | Обязательно. Секретный токен сообщества: Long Poll, сообщения, поддерживаемые групповые методы |
| `VK_USER_TOKEN` | Секретный пользовательский токен администратора для стены, фото, статистики, банов; без него эти методы откажут |
| `VK_GROUP_ID` | Обязательно. Положительный числовой ID сообщества |
| `DANIL_VK_ID` | Обязательно. Положительный числовой ID Данила; только он управляет ботом |
| `ANNA_AUTONOMY` | `true` для первоначального включения; при отсутствии — `false`. Дальше действует сохранённая настройка `/anna autonomy` |
| `DB_PATH` | `/data/shtab.sqlite3` |
| `ASSETS_DIR` | `/data/assets`: локальные JPEG/PNG до 8 MiB |
| `LLAMA_URL` | `http://127.0.0.1:8081`; разрешён только loopback, без ключей и внешнего AI API |
| `PORT` | `8080` — только проверка `/healthz`, интерфейса администрирования по HTTP нет |
| `TZ` | `Asia/Yakutsk` — отчёты, дневные лимиты, запрет публикаций на сегодня |
| `MAX_AUTONOMOUS_MESSAGES` | `30` в сутки суммарно для публичных ответов и личных сообщений |
| `MAX_POSTS_PER_DAY` | `2`; превышение требует отдельного подтверждения HIGH |
| `USER_COOLDOWN_SECONDS` | `120`; дополнительно максимум 6 обработанных обращений пользователя за 24 ч |
| `INITIATIVE_INTERVAL_MINUTES` | `0` — выключено; либо не менее `60`. Интервал отсчитывается по локальному журналу публикаций |
| `MODEL_PATH` | `/data/model.gguf` |
| `MODEL_URL`, `MODEL_SHA256` | Необязательно: смена модели только парой URL + точная SHA-256. По умолчанию зафиксирована проверенная Q4_K_M |
| `PARALLEL` | Документированное значение `1`; скрипт жёстко запускает `--parallel 1`, переопределение не увеличивает параллельность |
| `GOMAXPROCS`, `GOMEMLIMIT` | `1`, `96MiB`; ограничивают Go runtime, не общую память llama-server |

`.env.example` — образец; бинарник сам `.env` не загружает. Локально задавать переменные окружения или использовать Docker `--env-file`.

## Основные команды

```text
/anna
/anna status
/anna autonomy on
/anna autonomy off
/anna pause
/anna resume
/anna emergency-stop
/anna tasks
/anna content
/anna log
/anna approvals
/anna memory
/anna team
/anna publish идея поста
/anna report
/approve ACTION-идентификатор
/reject ACTION-идентификатор
```

Дополнительные команды:

```text
/anna knowledge Проверенные услуги, цены, контакты, условия
/anna goals Цели сообщества
/anna rules Правила тона и содержания
/anna handoff 123456
/anna takeback 123456
/anna blacklist 123456
/anna unblacklist 123456
/anna spam точная нежелательная фраза
/anna no-publish-today
/anna delegate mira задача
/anna do описание операции с точными ID
/anna schedule 2026-10-01T10:00:00+09:00 | идея поста
/anna tool {"tool":"vk.upload_photo","arguments":{"asset":"photo.jpg"}}
/anna tool {"tool":"vk.create_post","arguments":{"text":"Текст","attachments":"photo-123_456"}}
```

`handoff` передаёт человеку **конкретного пользователя по ID**; по неясной фразе «этому человеку» бот просит указать ID. `blacklist` — локальное прекращение ответов, **не бан в VK**. Бан выполняется отдельным `vk.ban_member` после подтверждения. `knowledge`, `goals`, `rules` заменяют соответствующее поле памяти; максимум 1500 символов.

## Ограничения и гарантии

- Реально проверены Go-код, SQLite, HTTP-протокол LLM и одна полная цепочка на настоящей Qwen3-0.6B через llama-server. VK в тестах подменён: токены, права и публикацию в вашем сообществе нужно проверить после настройки.
- 0.6B — маленькая модель, а не модель уровня ChatGPT. Возможны слабый русский, повторы, неверные решения проверяющего и отказ публикации из-за некорректного ответа. JSON-схема исправляет формат, но **не гарантирует качество и истинность текста**. Подтверждённые цены цитируются из базы; неизвестные не придумываются.
- На рабочей машине один успешный сценарий занял около 38 секунд. На Amvera с 0.5 CPU скорость и пиковая RAM **не измерены**. Файл модели около 378 MiB; контекст 2048, один слот, короткие ответы. Полная цепочка на слабом CPU может занимать минуты. Docker-образ и модель должны укладываться в дисковый лимит, но сборочные квоты зависят от платформы.
- Для безопасности **все редактирования постов пока HIGH**: нет надёжного автоматического доказательства малого охвата. Удаление поста и бан тоже HIGH; бан ограничен 24 часами. Неограниченной массовой публикации/модерации нет.
- Ева предлагает визуал текстом. Генератор изображений не запускается на 1 ГБ RAM. Можно загрузить свой JPEG/PNG в `/data/assets`, вызвать `vk.upload_photo`, затем прикрепить возвращённый photo-ID.
- `/anna report` считает подтверждённые действия, но не называет лучший пост без сопоставимой статистики охвата. `vk.get_recent_activity` возвращает локальные полученные события, не полную историю VK.
- Анна использует фиксированную проверяемую цепочку и команды делегирования; это не бесконечная свободная дискуссия агентов. Алекс не исполняет shell или произвольный код.
- Изменение тональности через `/anna rules` влияет на следующие inference-запросы. Для безусловной отмены уже готовых публикаций использовать `/anna no-publish-today` или `/anna emergency-stop`.
- При включении инициативы учитываются локальные публикации этого backend. Ранее опубликованные вручную записи не становятся автоматически частью локального контент-плана.
- Состояние паузы сохраняется после аварии. Неизвестные результаты требуют ручной проверки: автоматического «принудительного повтора» нет.
- Журнал действий хранится 90 дней, диалоги/обработанные события 30 дней. Неопределённые действия, очередь и ожидающие решения не удаляются по сроку; SQLite имеет жёсткий предел около 256 MiB. При исчерпании диска действия должны быть остановлены и база обслужена, а не удалена.

## Разработка и проверка

```sh
go test -race -timeout 60s ./...
go vet ./...
go build ./...
sh -n start.sh
# При работающем локальном llama-server:
SHTAB_LIVE_LLM=1 go test -run '^TestLiveLocalPipeline$' -v -timeout 8m
```

CI запускает unit/integration-тесты с подменой VK/LLM, vet, сборку и проверку shell. Локальный тест модели включается отдельно; не отправляет запросов в VK. Подробности: [docs/TEST_REPORT.md](docs/TEST_REPORT.md), методы: [docs/VK_TOOLS.md](docs/VK_TOOLS.md).
